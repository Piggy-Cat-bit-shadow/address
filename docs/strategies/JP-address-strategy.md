# JP 日本地址生成策略

| 项目 | 核心内容 |
|---|---|
| 主源 | Overture Maps addresses（当前批量候选）；Digital Agency ABR/Geolonia 为已验证可读的地址存在候选。 |
| 格式 / 邮编 | `〒<postcode> <都道府県><市区町村><町名><丁目><番><号>`；建筑名/室号缺失不补；源记录；格式门禁 `\d{3}-?\d{4}`。只清洗格式，不创造或按邻近地址补齐 |
| 行政区 | 日本数字厅 Address Base Registry/总务省行政区作为候选核验；当前源字段与 catalog 反查。行政层级必须与坐标反查一致；冲突时保留源值在隔离区并拒绝发布 |
| 住宅证据 | 明确住宅建筑证据；ABR 的地址存在不等于住宅用途。住宅证据必须来自明确建筑/用途字段，不能由地址存在推断 |
| 发布门禁 | 质量高于数量。仅发布 E3：地址存在与独立住宅用途证据同时成立；本国格式规定的必填组件缺一即淘汰，字段冲突拒绝合并；只允许可逆、可验证的格式规范化。 |
| 同步频率 | 每月检查上游版本；新快照通过门禁后原子切换，失败保留上一 active 快照。 |
| 验证 / 排除 | 2026-07-29 本地验证 Geolonia README 与新宿区 API 均 HTTP 200，返回町字、丁目、`rsdt`、坐标和 CSV 范围；这些只证明地址存在，不证明住宅用途。当前 Overture 快照在严格门禁下为 0，不发布。 |
| 策略版本 / 状态 / 更新 | 1.2 / 等待住宅用途关联 / 2026-07-29 |

- 默认 active 地址目标 40,000；都道府县、市区町村、町域单节点上限 1,500/200/50，后台可覆盖；只裁剪地址记录，行政区划与邮编目录保持完整。
- 同一源版本产生 0 条合格记录时标记 `SOURCE_QUALITY_FAILED`，只重查源版本元数据；上游版本或适配/清洗版本变化后自动重试。

统一证据等级、许可、配额与 VPS 边界见 [数据源与自动同步方案](../data-sources.md)。策略变化时同步更新本文件、实现与测试。
