# CN 中国地址生成策略

更新日期：2026-07-27

## 数据源

| 数据 | 来源 | 本地表 |
|---|---|---|
| 省、市、区县、乡镇街道 | [AreaCity](https://github.com/xiangyuecn/AreaCity-JsSpider-StatsGov) 发布数据 | `cn_admin_areas` |
| 住宅小区名称、登记地址、坐标 | 高德、百度、腾讯地点检索 API | `cn_communities_v2` |
| 平台原始证据 | 平台 POI ID、原始地址、原始坐标和响应摘要 | `cn_community_sources` |

生产数据只在服务器 `/root/address/data/address.sqlite`。仓库只提交表结构、代码和脱敏 fixture。

## 真实性

| 组件 | 规则 |
|---|---|
| 省/市/区县/乡镇街道 | AreaCity 层级校验后的真实名称 |
| 小区 | 高德、百度或腾讯返回的真实 POI 名称 |
| 登记地址 | 地图平台返回值；缺失时留空 |
| 坐标 | 平台真实坐标转换后的 WGS-84 |
| 楼栋 | 生成，`1–3栋` |
| 单元 | 生成，`1–3单元` |
| 楼层 | 生成，`2–6层` |
| 房间 | 生成，每层 `01–04室` |

中国住宅模式不使用 OSM 小区或内置小区词库。没有地图平台小区覆盖时不生成虚构住宅小区。

## 坐标与合并

- 高德、腾讯原始坐标为 GCJ-02，百度原始坐标为 BD-09。
- `cn_community_sources` 保留原始坐标和坐标系。
- `cn_communities_v2` 保存统一的 WGS-84 坐标，供全项目 R-tree、Google 地图和距离计算使用。
- 同省市区县、标准化名称一致且距离不超过 300 米的记录合并。
- 数据库同步等级为：单平台 L1、两平台 L2、三平台 L3；来源明细始终保留。对外地址模型只使用 L2/L3，单平台合格记录映射为 L2，多平台记录映射为 L3。

## 同步与 Key 轮换

地图 Key 通过 `/admin/` 写入 `control.sqlite`，使用服务器环境变量 `CONFIG_MASTER_KEY` 进行 AES-256-GCM 加密。每个平台支持多个 Key，按启用状态、剩余额度、权重、冷却时间和最近使用时间选择。

错误分类：

- QPS：指数退避后切换 Key。
- 每日额度：暂停到下一额度周期。
- 鉴权或参数错误：标记 `needs_review`。
- 网络异常：短暂冷却并重试其他 Key。

同步任务按城市、平台和页码记录到 `cn_sync_checkpoints`；任务状态保存到 `control.sqlite.sync_runs`。默认首批覆盖 43 个省会、直辖市和热门城市。

## 运行时

同步完成后 WebUI 与 API 只查询服务器 SQLite。中国住宅请求优先从 `cn_communities_v2` 按省市筛选并按种子稳定抽取；生成的楼栋、单元和房间不写回数据库，也不参与地图搜索。

地图链接：

- Google 坐标预览使用 WGS-84。
- Google 地址搜索包含真实登记地址和小区名。
- 高德链接将 WGS-84 转回 GCJ-02。
- 生成的楼栋、单元和房间不进入地图查询文本。

## 变更检查

修改数据源、字段真实性、坐标系、生成范围、去重距离、Key 轮换、同步流程或降级行为时，必须同时更新本文件、测试和公开说明。
